About Erasmus Life Housing & Platform Logic

Erasmus Life Housing (shortly ELH) is a specialized platform dedicated to helping students find accommodation. We partner with numerous landlords who offer various apartments and houses for rent. While for some landlords ELH is the exclusive booking platform, others list their properties in multiple places. Therefore, one of our primary tasks is to maintain accurate and synchronized data across the site.

Core Entities

The system's logic revolves around three key concepts:

  • Room: A single unit of personal space (usually a bedroom) where a student stays. This is the most granular level, where pricing and booking dates are managed.
  • Listing: A collective term for a unit that groups several rooms together. It represents shared areas (kitchen, bathroom, corridors) and can be referred to as an apartment, house, or condo.
  • Landlord (shortly LL): The individual or company owner to whom each Listing is attached.

URL Structure & Navigation

The platform uses unique IDs for each entity to manage links. Understanding these patterns is helpful for manual navigation or troubleshooting.

Landlord
  • Create: erasmuslifehousing.com/dashboard/admin/users/create - example
  • Edit: erasmuslifehousing.com/dashboard/admin/users/{landlord-ID}/edit - example
Listing
  • Create: erasmuslifehousing.com/dashboard/admin/houses/form - example
  • Edit: erasmuslifehousing.com/dashboard/admin/houses/form/{listing-ID} - example
    If the end of the link contains anything other than the existing listing-ID, it will be truncated and a new listing will be created with a new listing-ID.
Room
  • Create: erasmuslifehousing.com/dashboard/admin/listings/{listing-ID}/rooms/form - example
  • Edit: erasmuslifehousing.com/dashboard/admin/listings/{listing-ID}/rooms/form/{room-ID} - example
    If the end of the link contains anything other than the existing room-ID, it will be truncated and a new room will be created with a new room-ID in this listing.
    Rooms cannot exist without a listing. Even though room-IDs are unique, you need the listing-ID to build the edit URL.
Public View
  • Room Page: https://www.erasmuslifehousing.com/room/na/na-{room-ID} - example
    This page combines data from the Listing and the specific Room to show the user exactly what they are booking.

1. Introduction to the Extension

This extension is designed to supercharge your workflow on the Erasmus Life Housing platform. Its core philosophy is to automate repetitive data entry tasks using a standardized data format called u-JSON.

Almost all buttons injected by this extension onto the website have a unified green style, so you can easily distinguish them from the native interface.

Installation

  1. Download or clone the GitHub repository
  2. Open your browser (Chrome recommended) and navigate to chrome://extensions.
  3. Enable Developer mode in the top right corner.
  4. Click Load unpacked and select the downloaded extension folder.
  5. ELH Tim's helper should now be visible in the list of extensions.

Disclaimer

Due to very limited time constraints and the fact that I am still a student, this extension was developed with significant assistance from AI tools (initially VSCode + GitHub Copilot, and later Google Antigravity - which performed much better).

2. Extension Features by Button

Button to Paste u-JSON

Paste Universal JSON

This is the most powerful button on the page. It intelligently inserts u-JSON data from your clipboard to the relevant fields on whichever step of the room or listing edit page you are currently on.

Steps to use:

  1. Copy a valid u-JSON object (usually from AI or Spreadsheet).
  2. Go to any Listing or Room edit or creating page.
  3. Go to any page step (e.g. General Info, Features, Location).
  4. Click the Paste Universal JSON button on the bottom-right.
  5. The extension will fill out all matching fields at once of the current step page.
  6. All filled fields will be highlighted with green outline. If a field is already filled with the same value, it will be highlighted with grey-green outline.
Example of the floating "Paste Universal JSON" button injected into the landlord edit page and highlighted fields after pasting the u-JSON.

Buttons to Open Tabs

Steps to use:

  1. Go to the Listings Page on admin dashboard
  2. Use the search bar to filter the listings.
  3. Click to one of the buttons:
    • open all listings (X tabs) to open the "Edit Listing" page for every listing visible in your current search results.
    • open all rooms (X tabs) to open the "Edit Room" page for every room in every listing visible in your current search results.
    • open X tabs to open the "Edit Room" page for every room in this specific listing.
      This button visible even without any search.

in Options you can set with checkboxes:

  • Stay in same page after opening all tabs
  • Open all tabs in the same tab group
Example of these buttons injected into the listing search page.

Buttons to Generate Room Name or Description

Steps to use:

  1. Go to Room Creating or Editing page.
  2. Go to "Photos and description" step.
  3. Fill required fields.
  4. Click one of the AI buttons:

3. u-JSON

Universal JavaScript Object Notation or just u-JSON.
It is a special JSON structure designed by Tim, to store all data of all possible fields of ELH's landlord, listing and room forms at once.

Structure & Rules

  • json_meta: Can contains any metadata or comments of this JSON.
    Important: The field "json_type": "ELH_u-JSON_by_Tim_v1" is mandatory. The extension uses this specific key and value to verify that the pasted data is indeed intended for it and not just some random text.
  • room_data: Can contains any fields specific to the Room forms.
  • listing_data: Can contains any fields for the Listing/House forms.
  • landlord_data: Can contains any fields for the Landlord form.

4. Rooms Batch Runner

The Rooms Batch Runner is the flagship feature. It allows you to update multiple rooms across different listings in one go.

The Workflow

To update multiple rooms, follow these steps. For a visual demonstration, see the screenshots below.

  1. Prepare the data. You should have copied to the clipboard a spreadsheet where each row contains two columns:
    a direct link to edit the room and u-JSON with the information you want to change.
    To obtain this, carefully read the Google Sheets Mapping section.
  2. Open Options and scroll down.
  3. Paste the data into the "Rooms Batch Runner" text area. The extension will generate a preview table showing the URL status and u-JSON validity.
    Batch Runner Interface in Options
  4. To run, click ▶︎ Start Batch Process.
    Batch Runner Main Showcase Video

Batch Runner Options

▶︎ Start Batch Process

Starts opening tabs and applying data.

Auto-pause

To prevent your browser from freezing (or crashing), you can set an Auto-pause limit (e.g., "Auto-pause after 10 tabs"). The script will stop opening new tabs after the limit is reached, allowing you to save/close the opened ones before resuming.

Do it in background

If checked, the extension will attempt to perform actions with less focus stealing.
Note: Browser limitations may apply. For example, the script often cannot correctly interact with the "Blocked Dates" calendar picker when running in the background.

Tab Management

Once tabs are opened and processed, a new section appears to help you manage them:

  • Close All Tabs...: Closes all tabs opened by the batch runner.
  • Close Unchanged Tabs...: Closes tabs where no changes were needed.
  • Save & Close All Tabs...: Clicks the "Save" button on each tab and then closes it.
Batch Runner Saving Showcase Video

Be really careful with that feature!

Keep in mind, that it can change a lot of rooms at once, and if instructions will have mistakes or just something will go wrong, then it won't be easy for ELH, or especially for you, to restore everything to how it was.

5. Google Sheets Mapping

Most Batch Runner workflows start from a Google Sheet.

Main idea

Most landlords keep their apartment data in separate spreadsheets.
For example:
Quarto e Quartos (shortly QQ) Google Sheet
Place to Stay (shortly P2S) Google Sheet

ELH once tried to combine all landlords into a single large sheet called "Global Map 2018",
but keeping it updated turned out to be chaotic and unreliable.
Important: To all the mentioned tables, special access rights are required. Ask your mentor colleagues. Either they will give you access or they will provide an ELH account with this access.

So, I created a new spreadsheet, "ELH IT - LL's sheets to u-JSON",
Its main purpose is to map which row in a landlord's sheet corresponds to a room ID and listing ID in the ELH platform so we can operate on them programmatically.

What this sheet do:

  • using `=IMPORTRANGE` it imports the landlord's original table (stripping formatting) and allows us to edit freely.
  • To the left of the imported table the listing ID and room ID are entered manually.
  • Based on those two columns, a simple formula builds a direct link to the room/listing edit/view page.
  • Each landlord has a separate tab.
Structure of the spreadsheet.

Now the most interesting part - converting messy landlord data into a structured u-JSON.
Bassicly we have three ways to obtain the two-column table required by the Batch Runner:

  1. Write it manually.
    👍Pros: It is possible.
    👎Cons: Obviously, nobody will do this.
  2. Create a spreadsheet function.
    👍Pros: Once configured, it works automatically for any number of rooms.
    👎Cons: Each landlord's sheet is different, so custom formulas may be required and can break if the source sheet changes.
  3. Let AI figure it out.
    👍Pros: It’s universal. You can tell the AI what data you need, and you usually don't even have to explain the LL's logic.
    👎Cons: AI still can make errors. Also, if the dataset is huge, it may take a long time to think and then even can screw you over.

Examples

  • Method 2
    I managed to create one such function for updating blocked dates for the QQ table. So you just need to copy these two columns.
  • Method 3
    Copy the column with the edit-room link and the other useful columns, paste them to the AI bot, explain what you want and how to interpret the landlord's data, then copy the table that AI returns.
  • Method 1+3
    In this case, I combined two methods.
    First, I manually looked through and found which link of this LL corresponds to which ELH's room...
    Then I went through all the links and copied the first available month and rent from the pages into separate columns (because this needed to be updated).
    Then I copied these columns together with "edit room" and pasted them into my AI bot.
    In the end, as usual, I got a table with a URL to edit room column and u-JSON column.

You are a bot that helps create universal JSON used for inserting and updating data on the platform.
This JSON must always have a clear hierarchy and all keys must be named exactly as in my example.

If I ask you to create JSON for a room, the root must contain only json_meta and room_data.
If I ask to create JSON for a listing/house/address, the root must contain only json_meta and listing_data.
If I ask to create JSON for a landlord/person/company, the root must contain only json_meta and landlord_data.

The JSON should include only keys for which there is data.
Fill values based on all data I provide, including photo analysis where applicable.
After you send the complete JSON, briefly explain which values you chose and why, and list any uncertain guesses so I can confirm or reject them.
Ask me if any critical data is missing.
Your explanations should be in English, but if I address you in Ukrainian, reply in Ukrainian.
Keep answers concise and without unnecessary introduction.
Messages I send for analysis are usually in English or Portuguese.

1. `url edit room` - link to edit a specific room, like: https://www.erasmuslifehousing.com/dashboard/admin/listings/{listingsID}/rooms/form/{roomID}
